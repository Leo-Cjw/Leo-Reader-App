# Reader 0.64.0

本版本关闭 AI 配置跨存储变更期间的可见中间态。0.63 已让 `update/reset` 按调用顺序执行并在失败时补偿凭据，但 Keychain 修改完成、非密钥设置尚未提交的短暂窗口内，设置读取、连接测试或模型目录仍可能把新密钥与旧端点组合。现在这些对外读取都会在线性化变更完成后再解析配置，避免新凭据被发送给旧作用域。Schema 保持 v12，`settings.json` 格式保持 version 1，用户数据、备份与导入格式不变。

## AI 配置一致读取

- 对外设置读取、连接测试与模型目录在解析设置或读取 Keychain 前，等待调用时已经排队的 AI 变更完成。
- 设置更新仍先安全写入凭据、再原子保存非密钥配置；运行中 AI 服务继续使用变更前的完整内存配置，只有保存成功后才整体切换。
- 更新失败且补偿完成后，等待中的读取解析恢复后的旧状态；成功时只解析完整的新状态。
- 内部提交路径使用不等待队列的快照方法，避免当前事务等待自身；读取屏障不改变 0.63 的调用顺序与失败恢复语义。
