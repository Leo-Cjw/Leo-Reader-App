# Reader 平台导入 SOP

本文档适用于 Reader 1.1.1（build 111、SQLite schema v13），说明各平台应该从哪个入口导入、如何判断成功，以及失败后的安全处理方式。平台能力等级和内容边界始终以 [PLATFORM_SUPPORT.md](PLATFORM_SUPPORT.md) 为准；本 SOP 不扩大平台承诺。

## 1. 导入前检查

1. 优先使用 Mac App。抖音专用导入依赖 Electron 隔离会话，源码 Server 模式不支持。
2. 确认来源内容可公开访问。Reader 不绕过登录墙、付费、地区限制、DRM、已删除或私密状态。
3. 在“添加”窗口先选择目标资料夹，再创建导入或订阅。
4. 网页、抖音和附件进入持久化导入队列；关闭窗口或重启应用不会丢失未完成任务。
5. 不要把“任务完成”等同于“全部媒体离线”。完成后仍需查看文章的“离线完整”“部分离线”或“仅正文离线”状态。

## 2. 平台入口速查

| 平台 | 使用入口 | 成功标准 |
| --- | --- | --- |
| 抖音 | “添加 → 网页 URL” | 作品元数据和可播放媒体已保存；有字幕/章节或本地转写时正文可全文搜索 |
| 微信公众号 | “添加 → 网页 URL” | 标题、作者、正文、表格、代码块和可下载图片已保存 |
| CSDN、掘金 | “添加 → 网页 URL” | 公开正文被通用提取；图片完整度以阅读页状态为准 |
| 知乎、今日头条 | “添加 → 网页 URL” | 公开静态正文或元数据被提取；动态或受限页面不保证 |
| B站、小宇宙 | “添加 → 网页 URL” | 只按通用网页验收公开文本或元数据，不验收离线媒体 |
| 其他公开网页 | “添加 → 网页 URL” | Readability 正文已保存；可下载正文图片最多 16 张 |
| RSS / Atom | “添加 → 自动订阅” | 来源创建成功，首轮同步完成，后续按频率增量更新 |
| YouTube | “添加 → 自动订阅 → YouTube 频道” | 频道 Feed 条目和元数据进入资料库 |
| X | 配置连接器后“添加 → 自动订阅 → X 用户” | 官方账号时间线完成首轮同步并保存增量游标 |
| 微博 | 配置连接器后“添加 → 自动订阅 → 微博用户” | 官方 CLI 账号时间线完成首轮同步 |
| 小红书 | 无 | 当前不支持，不建立登录、抓取或媒体导入任务 |

## 3. 抖音作品

### 标准流程

1. 在抖音复制作品链接或完整分享口令。
2. 打开 Reader“添加 → 网页 URL”，粘贴内容。输入不得超过 4096 字符，且只能包含一个可信抖音链接。
3. 选择资料夹并确认。Reader 会把短链和跟踪参数规范为稳定作品 ID，避免同一作品重复入库。
4. 在“导入队列”观察解析、下载、保存、转写和索引阶段。
5. 若任务显示“等待登录”，点击“登录并继续”，只在 Reader 打开的隔离窗口中完成登录。验证码需要用户自行处理，Reader 不自动识别或绕过。
6. 若作品没有平台字幕或章节，任务会等待本地转写模型。macOS 13.3+ 可点击“安装模型”下载并校验约 466 MiB 的 Whisper small，也可选择“暂不转写”先保留媒体；macOS 12/13.0–13.2 只能跳过本地转写。
7. 完成后打开文章，检查标题、作者、发布时间、媒体时长/图片数量、离线状态，并用字幕或转写中的关键词做一次全文搜索。

### 内容验收

- 视频：优先保存不超过 100 MB 的带声 H.264 1080p MP4；候选不可播放或超限时刷新详情并降至 720p。所有视频候选失败时任务失败，不创建空壳文章。
- 图文：最多保存 30 张图片，至少成功一张才创建文章。背景音乐作为独立音频附件；个别图片或音乐失败时任务可以完成，但会标记“部分离线”和缺失数量。
- 转写：顺序固定为平台字幕/章节、本地 Whisper、等待用户安装模型。本地推理期间队列会在转写阶段持续显示进度；只有非空时间戳分段才算成功，随后写入 Markdown 与 WebVTT，并重建全文与 RAG 分块索引。

### 异常处理

- 登录失效：从失败任务重试；只有队列明确要求登录时才打开隔离登录窗口。
- 验证码：在可见登录窗口人工完成；若平台持续阻止访问，取消任务，不反复自动尝试。
- 私密、付费、删除、地区限制或 DRM：属于明确不支持，停止重试。
- 等待模型：安装模型后点“继续”；不需要转写时选择“暂不转写”。媒体已成功保存的转写失败任务只重试转写。
- 空转写或 Helper 异常：文章和媒体保持不变，不生成空 WebVTT；可在失败任务中重试转写，或明确选择“暂不转写”。
- 过期媒体地址：直接重试任务，Reader 会重新获取作品详情，不复用旧签名地址。
- 清除登录态：在“设置 → 抖音隔离会话”点击“彻底清除会话”。这不会删除已经保存的文章或媒体。

## 4. 微信公众号

1. 复制 `mp.weixin.qq.com` 的文章地址。
2. 在“添加 → 网页 URL”粘贴地址，选择资料夹后确认。
3. 完成后检查标题、公众号/作者、正文、表格、代码块和图片。微信验证页会使任务失败，不会保存成文章。
4. 若出现环境验证，先在系统浏览器确认文章仍公开可访问，再从导入队列重试。持续验证时保留失败状态，不把验证页当作正文。

内嵌音频和视频不属于当前保证范围。重新导入同一 URL 会原位更新文章并保留资料夹、标签、高亮和版本历史。

## 5. 通用网页平台

CSDN、掘金、知乎、今日头条、B站、小宇宙和其他公开网页共用以下流程：

1. 在“添加 → 网页 URL”粘贴单个公开 HTTPS 页面地址。
2. 选择资料夹并确认，等待导入队列完成。
3. 打开文章检查标题、作者、正文结构和离线完整度。通用流程最多读取 4 MB 网页响应，保存代表图片和最多 16 张通过安全校验的正文图片。
4. 若只得到元数据、正文缺失或任务失败，先确认页面无需登录且静态可访问；仍失败则按当前平台边界记录为“不支持该页面”，不要把浏览器中可见等同于 Reader 能稳定提取。

这些平台当前没有登录会话、验证码自动化或专用动态渲染。B站与小宇宙不验收离线视频/音频；CSDN、掘金、知乎的专用适配属于下一阶段计划。

## 6. RSS、YouTube、X 与微博订阅

### RSS / Atom

1. 打开“添加 → 自动订阅”，选择“RSS / Atom”。
2. 填写订阅名称、Feed 地址和同步频率并确认。
3. 检查首轮新增数量；后续在“内容来源”查看最近状态、失败退避和下次同步时间。

Reader 只保存 Feed 实际提供的正文和媒体信息，不保证回源网页的全部内容。

### YouTube

1. 打开“添加 → 自动订阅”，选择“YouTube 频道”。
2. 填写频道主页、`/channel/UC…` 地址或官方 Feed 地址。
3. 验收频道条目和元数据进入资料库。

YouTube 在 1.1.1 仅支持频道订阅，不支持任意单视频下载或离线媒体。

### X

1. 打开“添加 → 自动订阅 → 配置社交连接器”。
2. 在 X Developer Console 获取具备所需权限的 Bearer Token，在 Reader 中先测试再保存。Token 只进入 macOS Keychain。
3. 返回“自动订阅”，选择“X 用户”，填写用户名或个人主页并确认。
4. 检查首轮同步和限流状态。Reader 使用官方 API 与 `since_id` 增量游标。

账号权限、API 配额与费用由 X 决定；任意单帖媒体离线不作保证。

### 微博

1. 安装官方 CLI：`npm install -g @weibo-ai/weibo-cli`。
2. 在终端运行 `weibo auth login --device`。
3. 打开“添加 → 自动订阅 → 配置社交连接器”，确认 Reader 能检查到 CLI 登录状态。
4. 返回“自动订阅”，选择“微博用户”，填写数字 UID 或个人主页并确认。

Reader 只调用官方 CLI 读取账号时间线，不读取或复制 CLI 管理的 OAuth 令牌；任意单帖媒体离线不作保证。

## 7. 不支持的平台与操作

- 小红书当前明确不支持，也不在当前路线。不要在 Reader 中建立登录或媒体抓取流程。
- 所有平台都不提供去水印、批量抓取、主页采集、评论采集或再发布。
- Reader 不绕过验证码、登录墙、付费、私密、删除、地区限制或 DRM。
- 不要通过放宽 SSRF、重定向、MIME、文件签名、大小或路径校验来让某个页面“导入成功”。

## 8. 故障记录与复验

报告平台问题时记录 Reader 版本、平台、入口、任务状态、阶段、进度、公开错误提示和离线完整度；不要复制 Cookie、Bearer Token、OAuth 信息、抖音签名 URL 或本机磁盘路径。

修复后至少复验：

1. 相同输入不会产生重复文章。
2. 文章正文可搜索，媒体能在断网后播放或明确显示缺失。
3. 任务失败、取消或重启后没有空壳文章和遗留临时文件。
4. Markdown ZIP 与完整备份恢复后，正文和已保存附件仍可用。
