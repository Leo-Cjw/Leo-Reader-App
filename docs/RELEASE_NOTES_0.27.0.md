# Reader 0.27.0

本版本让自动订阅和持久化导入队列感知 Mac 的睡眠、网络、电量与系统资源状态。用户数据结构保持 schema v10，来源同步协议、连接器凭据和既有文章均不迁移；`/api/health` 只增加脱敏后台状态。

## 后台调度策略

- Mac 睡眠时暂停导入队列和自动来源同步，唤醒后重新读取网络、电量与热状态，再决定是否恢复。
- Electron 报告严重/临界热状态，或系统把 CPU 速度限制到 50% 以下时，暂停全部后台 worker，避免继续抢占受限系统资源。
- 网络离线时只暂停自动来源同步，不把不可达误记为来源失败或推进退避计数；本地附件导入不受影响。
- 电池供电且电量不高于 20% 时只暂停自动来源同步；接入电源或电量恢复后继续。电量来自只读的 `/usr/bin/pmset -g batt`，每五分钟刷新一次。
- 用户点击“立即同步”仍是明确的前台操作，不受自动调度暂停开关限制。

## 状态合并与恢复安全

- 服务端把资料库待恢复锁、睡眠、系统资源限制、离线和低电量合并为单一串行策略。
- 某一个条件解除时，只要仍有其他暂停原因，就不会提前恢复对应 worker；取消资料库恢复也不会绕过仍存在的离线、睡眠或电量约束。
- 离线状态在应用启动时先于可能较慢的电量查询发布，保证在自动调度首轮运行前生效。
- `/api/health` 公开在线、低电量、系统受限、worker 是否暂停及枚举原因，不返回电量百分比、网络标识、命令输出或本机路径。

## 订阅中心

- 订阅中心以可播报的状态文字显示恢复锁、睡眠、系统受限、低电量或离线原因。
- 状态提示沿用现有暖白桌面体系；来源开关、同步频率、立即同步、删除与 OPML 操作保持原位。
- 隔离真实界面回归确认低电量暂停提示、ARIA status 和手动同步按钮均可见；隔离数据库与测试标签页已清理。
- Universal App 在当前 x64 Mac 使用独立资料目录完成真实启动和关闭；本地日志记录 0.27.0/schema v10，数据库 `integrity_check` 为 `ok`，隔离目录随后移入废纸篓。

## 已知边界

- 自动测试以可控事件替身覆盖 suspend/resume、网络、电源和热状态；本轮没有在真实低电量或睡眠中的 Mac 上等待完整周期。
- Electron 的在线判断为离线强信号；显示在线不保证某一个远程来源必然可达，既有逐来源失败退避仍负责该边界。
- Developer ID 正式签名、Apple 公证、自动更新、Apple Silicon 真机安装升级和 Gatekeeper 验收仍未完成。
