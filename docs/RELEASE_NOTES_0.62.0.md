# Reader 0.62.0

本版本修复不同设置并发保存时的丢更新风险。Reader 的设置文件本来已经使用私有临时文件与原子 rename，但多个请求仍可能从同一旧内存快照生成完整 JSON，最终由最后完成的写入覆盖其他设置。现在完整保存事务按调用顺序执行。Schema 保持 v12，`settings.json` 格式保持 version 1，用户数据、备份与导入格式不变。

## 设置保存事务串行化

- AI、导入暂停、通知、自动恢复点、Spotlight 与语义检索设置共享同一个进程内保存队列。
- 每项操作会等待前一项完成，再读取最新内存状态、生成下一状态、原子持久化并更新内存，不再基于过期的全量快照互相覆盖。
- 现有随机私有临时文件、`0600` 权限、独占创建与原子 rename 保持不变。
- 写入失败仍会拒绝对应调用，但排队状态会安全恢复，后续保存不会被永久阻塞。
