# Reader 0.19.0

本版本把 Reader 的可迁移导出补成可安全往返的完整链路：用户可以预检 Reader Markdown ZIP、逐篇选择内容、指定目标资料夹，再把文章和附件带回任意 Reader 资料库。

## 选择性导入

- “添加”窗口新增 Reader ZIP 入口；预览通过前不写入资料库。
- 预览列出文章、附件、高亮、标签和冲突状态，可全选或逐篇勾选。
- 用户统一指定目标资料夹；已有相同 Reader ID 或原链接的内容默认跳过，不隐式覆盖。
- 导入恢复标题、来源、作者、类型、语言、发布时间、正文、摘要、标签、高亮、附件、收藏、已读和阅读进度。
- 附件按 SHA-256 复用本地文件，正文中的旧附件 URL 或导出相对路径改写为新的同源端点。

## 可往返导出格式

- Markdown 导出格式升级到 v3，继续提供可独立使用的标准 Markdown、相对附件和 manifest。
- 每篇文章新增 `records/` sidecar，保存 Reader 无损重新导入所需的原始正文与本地状态，避免把展示型“附件 / 高亮与批注”附录误当正文。
- 继续接受 0.18 生成的 v2 包；兼容模式从受限 frontmatter 重建内容，并剥离 Reader 在末尾生成的附录。
- schema 仍为 v9，0.18.x 用户升级不需要数据库迁移。

## 安全与隐私

- 只接受 Reader `reader-markdown-export` v2/v3，拒绝完整备份或任意 ZIP 混入。
- 拒绝绝对路径、路径穿越、反斜杠、符号链接、加密条目、重复/未知文件和超限展开数据。
- 压缩包上限 2 GB、展开总量上限 5 GB、单附件上限 100 MB、单次最多 500 篇；附件实际大小和 SHA-256 必须与清单一致。
- 预览 token 不暴露本机路径；暂存目录/文件权限为 `0700/0600`，取消、提交或 24 小时过期后自动清理。
- 导入包中的 URL 只允许 HTTP(S)，扩展元数据、ID、高亮锚点和清单统计均有边界校验。

## 质量门禁

- 66 项自动测试覆盖 v3 子集往返、重复导入幂等、ID/URL 冲突、v2 兼容解析、路径攻击、附件篡改、暂存权限与过期清理，并继续覆盖全部既有产品主链路。
- TypeScript/Vite 生产构建通过，依赖审计为 0 个已知漏洞；新增界面在 1280×720 的浅色和深色主题完成真实布局检查。
- 10,003 个本地片段、30 次查询的独立检索基准 p95 为 27.09 ms，低于 250 ms 门禁。
- Universal App 检出 x86_64 与 arm64 双架构，版本元数据为 0.19.0，ad-hoc 深度签名验证通过；DMG 通过 `hdiutil verify`。
- `Reader-0.19.0-universal.dmg` 大小为 255,723,537 字节，SHA-256 为 `3b77d622beebb16a07f62bdb9517f96c3816496ae9942e04ca813b630a39419c`。

## 已知边界

- v2 包没有无损 sidecar；兼容导入依赖 Reader 0.18 的固定 frontmatter 与末尾附录格式。v3 包应作为后续往返的首选。
- 未携带附件的导出包不能恢复原始附件字节。
- Developer ID 正式签名、Apple 公证、自动更新和双架构真机安装升级验收仍未完成。
