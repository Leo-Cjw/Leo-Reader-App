# Reader 0.37.0

本版本为 Electron 阅读界面增加可控崩溃恢复。渲染进程异常退出不再把窗口留在失效页面：Reader 会说明已持久化资料仍安全，让用户选择重新载入界面或安全退出，并把有限故障原因写入可清除的本地诊断。SQLite schema 保持 v10，HTTP API、设置、文章、附件、备份和导入导出格式均不变。

## 界面恢复

- 主窗口在初次成功加载后监听 Electron `render-process-gone`；初次加载失败仍走既有启动故障路径，退出期间、旧窗口和重复事件不会弹出恢复提示。
- 故障发生后立即暂停向失效渲染器交付外部 URL。用户确认“重新载入界面”后，只重建沙箱化页面；本地 HTTP 服务、SQLite、导入 worker 和订阅调度保持运行。
- 新页面完成加载后恢复既有单向 IPC 队列，崩溃期间收到的合格 `reader-local://add` 地址不会丢失，也不会绕过添加窗口确认。
- 用户选择退出时复用既有安全关闭顺序。原生提示明确区分已经写入的数据与尚未自动保存、可能丢失的临时界面输入。

## 隐私安全诊断

- 新增 `renderer_gone` 本地事件，只允许 Electron 官方原因枚举；未知值写作 `unknown`。
- exit code、进程 ID、页面 URL、磁盘路径、堆栈、标题、正文和未保存输入均不会进入日志。
- 数据安全中心用“内存不足”或“界面进程异常退出”的中性文案显示该事件；日志仍不自动上传，并继续受 1.5 MB 有限轮转、导出重清洗和用户清除控制。

## 验证

- 新增控制器测试覆盖确认重载、安全退出、重复提示抑制、旧窗口/退出流程忽略与诊断字段收敛。
- 修复服务端集成测试的清理竞态：每个用例统一先停止 worker 和本地服务，再删除临时资料库；连续两轮独立回归通过。
- `npm test`：106/106 通过；`npm run build`：生产构建通过；`npm run audit:dependencies`：生产依赖 0 漏洞，完整树仅保留已评估的构建工具公告。
- 在最终 Universal App 的隔离资料库中通过 DevTools `Page.crash` 强制终止真实渲染进程：原生恢复提示成功出现，本地健康检查继续返回 0.37.0，崩溃前写入的 QA 文章可完整回读，诊断只新增一条 `{ reason: "crashed" }`。确认重载按钮后的控制器行为由异步单元测试覆盖；当前自动化宿主未获 macOS 辅助功能权限，未把物理点击包装成已完成的真机步骤。
