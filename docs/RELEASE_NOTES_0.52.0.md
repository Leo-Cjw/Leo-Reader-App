# Reader 0.52.0

本版本把“备份文件已写出”与“恢复点已经可读验证”合并为同一个成功条件。所有新建完整备份必须在返回成功前重读最终产物；Schema 保持 v12，现有文章、附件、设置、旧备份和恢复格式不变。

## 创建时流式验证

- SQLite `VACUUM INTO` 快照先执行 `integrity_check`，不再把仅完成文件写入视为可用恢复点。
- 明文 ZIP 完成后以 lazy entry 流重读数据库、精确 manifest 字节和全部附件，逐项核对真实长度与 SHA-256。
- 同一遍读取继续执行路径、反斜杠、符号链接、重复/未知条目、最多 100,000 项和最多 5 GB 展开量边界。
- 验证过程不会把整套附件再次解压到磁盘；大资料库增加一次顺序读取和哈希，不增加一份完整附件副本的峰值空间。
- 任一缺失、损坏、哈希不符或结构异常都会删除本次最终归档并返回失败，因此诊断日志和 UI 不会记录虚假成功。

## 加密输出认证回读

- 加密路径先验证权限受限暂存区中的完整 ZIP，再执行既有 scrypt + AES-256-GCM 整包加密。
- 最终 `.readerbackup.enc` 会立即使用当前内存口令认证解密到哈希 sink，不落盘第二份明文，并要求与已验证 ZIP 的 SHA-256 完全相同。
- 口令仍不进入 SQLite、manifest、验证凭据、日志、设置、导出或待恢复标记。

## 可见验证状态与兼容

- 成功后在 `data/backups/` 写入权限为 `0600` 的小型验证凭据，只含备份 ID、严格文件名、字节数、归档 SHA-256 和验证时间。
- 数据安全中心对匹配凭据的新包显示“创建时已校验”；0.51 及更早备份、缺失凭据或被篡改凭据显示“恢复时校验”，但仍可下载和使用既有恢复时完整验证。
- 自动恢复点轮转只删除对应自动包及其验证凭据，不会触碰手动、加密、修复前或恢复前备份。
