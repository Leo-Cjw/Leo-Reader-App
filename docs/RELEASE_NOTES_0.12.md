# Reader 0.12.0

本版本把文章助手升级为可核对的本地优先 RAG：先在设备上找到相关原文，再回答，并让每条引用可以回到来源片段。

## 本地分块与增量索引

- Schema v5 新增 `article_chunks` 与 `chunk_search`，按 Markdown 标题和自然段生成约 900 字符、最多 1,400 字符的确定性片段。
- 片段记录稳定 ID、标题、原文起止偏移和 SHA-256；拉丁文字使用 FTS5，中文使用词组候选与本地加权排序。
- 文章创建、正文编辑、导入最终化和版本恢复都在同一事务中重建对应片段；升级只回填未索引文章。

## 当前文章与整个资料库

- 文章助手“对话”新增“当前文章 / 整个资料库”范围切换。
- 本地模式提供透明的提取式回答，正文使用 `[1]` 标记，下面显示原文引用卡片、来源、标题和检索轨迹。
- 点击引用卡片会打开来源文章，并显示带段落编号的原文定位卡；关闭后继续正常阅读。
- 弱相关结果经过词组覆盖与相对分数门槛；证据不足时返回空引用，不用无关段落填充答案。

## 远程最小披露

- 配置网关后仍先在本机检索；最多发送 8 个命中片段，每个最多 2,000 字符，不发送整篇文章或整个资料库。
- 没有命中证据时不调用远程服务。
- 网关返回的 `citationIds` 只能引用本次已发送的候选集合，无法伪造资料库中的其他来源。

## API 与性能

- `GET /api/ai/index` 返回索引版本、活动文章数、片段数和待索引数。
- `POST /api/ai/search` 提供纯本地候选检索；文章对话 API 返回 `scope`、`citations` 和检索轨迹。
- `npm run benchmark:rag` 建立 10,003 个片段并执行 30 次中英文检索，p95 门禁为 250 ms。本轮并发门禁实测 p95 为 40.35 ms。
