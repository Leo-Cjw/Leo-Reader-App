# Reader 0.33.0

本版本补齐导入队列的用户暂停与继续控制。文章、附件、任务状态和尝试次数仍使用既有 schema v10 与持久化队列；新增的暂停偏好属于本机运行设置，不修改数据库、备份或 Markdown 往返格式。

## 用户可控队列

- 导入队列窗口新增“暂停队列 / 继续队列”按钮。暂停会让当前已领取任务安全完成，然后不再领取下一项；pending 任务和已暂存附件保持原位。
- 标题栏区分“正在处理”和“已暂停”，队列窗口显示手动、资料恢复、Mac 休眠或系统资源受限等脱敏原因。
- 按钮使用原生 `aria-pressed`，状态说明由 polite live region 播报；暂停期间的任务轮询降为五秒，减少无效本地请求。

## 持久化与安全合并

- 新的 `PUT /api/import-jobs/state` 只接受布尔 `paused`，响应返回与 `/api/health` 相同的后台状态。
- 用户偏好原子写入权限为 `0600` 的 `data/settings.json`。保存 AI 设置或恢复 AI 默认值不会覆盖导入偏好；暂停记录不含任务载荷、URL、文件名、路径或凭据。
- Reader 启动时先读取偏好，以暂停态创建 worker，再开放本地服务；不会在恢复暂停状态前短暂领取 pending 任务。
- 用户继续只清除 `user` 原因。资料恢复锁、Mac 睡眠和严重系统限制仍能独立保持暂停，任何一个原因未解除时都不会恢复 worker；来源订阅不受用户导入暂停影响。

## 兼容性

- SQLite schema 保持 v10；导入任务、文章、附件、索引、备份和 Reader Markdown ZIP 格式不变。
- 旧版没有 `imports` 设置段时安全默认为继续处理；0.33 写回设置时保留既有 AI 配置与 Keychain 边界。
- 修正文档中“PDF.js 仍与主进程同进程”的过期描述；0.32 建立的一次性解析进程继续生效。

## 已知边界

- 暂停不是强制取消：已运行的单项任务会完成，因此控制请求可能等待当前任务结束。失败任务仍需用户明确重试。
- 当前包仍缺少真实 Apple Developer ID、公证、正式 GitHub Release、Apple Silicon Gatekeeper/跨版本升级验收，以及启用 VoiceOver 的完整人工听读。
