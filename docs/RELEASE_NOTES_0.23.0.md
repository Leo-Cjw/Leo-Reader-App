# Reader 0.23.0

本版本消除长正文对资料列表的放大效应，并修复文章卡片的嵌套交互语义。列表现在只传输展示所需摘要，完整正文仅在用户选中单篇内容后读取；打开文章和进入批量选择改为同级原生按钮，读屏与键盘焦点不再落入“按钮中嵌按钮”的冲突结构。数据库 schema 保持 v10，不触发迁移。

## 列表摘要与按需正文

- 数据库分页新增 `includeContent` 选项；默认值保持 `true`，既有 `listArticles()` 和内部调用继续获得完整文章。
- `GET /api/articles` 固定使用显式列投影，不返回 `content`；`GET /api/articles/:id` 仍返回完整正文。
- 前端引入 `ArticleSummary`，列表状态不再保留正文副本。选中文章后单独读取详情，快速切换时以请求代次丢弃过期响应。
- 新建、编辑、标记已读、标签更新、翻译与创作结果会同时刷新当前详情和不含正文的列表摘要。
- 服务端与数据库测试分别锁定摘要省略正文、详情保留正文以及内部兼容契约。

## 文章卡片语义

- 卡片外壳恢复为非交互 `article`，整卡打开和右上角选择改为两个同级原生按钮，不再嵌套交互控件。
- 原生打开按钮提供可见键盘焦点，并沿用浏览器的 Enter/Space 激活语义。
- 批量模式移除整卡打开按钮，每张卡只向辅助技术暴露一个选择或取消选择动作；鼠标仍可点击整张卡快速切换。
- 装饰性的来源标记、摘要和预览图不再给按钮制造重复名称。

## 10 万条长正文门禁

- `npm run benchmark:library` 会把首屏中的 97 篇文章扩展为每篇 100 KiB 正文，先量化完整响应，再测量摘要分页。
- 同一首屏完整载荷为 10,298,374 字节，摘要载荷为 57,074 字节，减少约 99.45%，低于 512 KiB 门禁。
- 100,003 条最终基准中：统计 p95 152.75 ms、首屏 49.40 ms、第二页 18.05 ms、中段游标 17.20 ms、未读 37.58 ms、英文搜索 147.65 ms、中文搜索 45.79 ms，全部低于 250 ms 门禁。
- 门禁还会拒绝摘要结果中出现 `content`、首屏载荷没有真实超过阈值、分页重复、计数不完整或任一交互超时。

## 质量验证

- 80 项自动测试和 TypeScript/Vite 生产构建通过。
- 真实浏览器回归确认 3 张文章卡对应 3 个打开按钮和 3 个选择按钮，交互式卡片外壳为 0、嵌套按钮为 0；批量模式每张卡仅保留一个选择控件。
- 浏览器完成文章打开、正文详情读取、批量选择及取消选择，控制台没有警告或错误。
- `npm audit --audit-level=moderate` 报告 0 个已知漏洞。
- 10,003 个本地 RAG 片段、30 次查询的检索基准 p50 为 44.72 ms、p95 为 51.93 ms，低于 250 ms 门禁。
- Universal App 检出 `arm64` 与 `x86_64` 双架构，版本元数据为 0.23.0，ad-hoc 深度签名验证通过；DMG 通过 `hdiutil verify`。
- `Reader-0.23.0-universal.dmg` 大小为 255,169,448 字节，SHA-256 为 `df20fefd63a08703fe90a1ce41b9876232c28ebc413ec18b1a2dc49b7177d1f3`。

## 已知边界

- 当前只完成文章列表这一条高频路径的语义修复；侧栏、模态框、编辑器、高亮批注和完整焦点顺序仍需系统性无障碍审计。
- Developer ID 正式签名、Apple 公证、自动更新和 Apple Silicon 真机安装升级验收仍未完成。
