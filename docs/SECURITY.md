# Reader 安全边界

## 默认信任模型

Reader 只监听精确的 IPv4 回环地址 `127.0.0.1`。本地 HTTP API 没有账号系统，因此服务构造会在任何数据目录、SQLite、后台任务或 socket 初始化之前拒绝 `0.0.0.0`、主机名、IPv6 和其他监听地址；`READER_HOST` 不能用于把服务暴露到局域网或公网。

回环服务要求每个请求的 `Host` 精确匹配本轮实际随机端口，阻止把攻击者域名 DNS rebinding 到 Reader。浏览器发送 `Origin` 时只能是同一回环 origin；发送 `Sec-Fetch-Site` 时只能是 `same-origin` 或 `none`。三项检查在 URL、路由、请求体和 SQLite 之前执行，失败统一返回 403。没有浏览器来源头的 Electron 主进程、Share 文件桥与同机 CLI 仍可调用；这不是面向已经取得当前用户权限进程的身份认证。

全部 HTTP 响应（包括静态界面、JSON、错误、导出、缩略图、附件与 Range）统一声明 CSP `frame-ancestors 'self'`、X-Frame-Options `SAMEORIGIN`、CORP/COOP `same-origin`、无相机/地理位置/麦克风权限、`no-referrer` 和 `nosniff`。同源允许值是为保留 Reader 内部 PDF `<object>` 与本地媒体加载；跨源页面不能把 Reader 页面或私有资源作为 frame/object 使用。HTML 自身的更完整 CSP 与 Electron 全权限拒绝继续叠加生效。

Reader 启动时把默认数据目录权限设为 `0700`，数据库及现有 WAL/SHM 文件设为 `0600`。这限制其他本机用户直接读取资料库，但不能防御已经取得当前用户权限或设备解锁权限的进程。

## 网络导入

- 仅允许 HTTP/HTTPS。
- 每一跳解析全部 DNS 结果；任一结果属于环回、私网、链路本地、CGNAT、IPv6 ULA、保留地址或云元数据地址即拒绝。URL 中的用户名或密码也不被接受。
- 实际 HTTP/HTTPS 连接只使用刚刚通过校验的具体公网 IP，并保留原域名完成 Host、TLS SNI 与证书身份验证；禁用跨请求连接复用。每次重定向重新解析并绑定，避免 DNS rebinding 在检查后把连接切换到内网。
- 限制重定向次数；15 秒超时覆盖连接和完整响应体。gzip、deflate 与 Brotli 在解压后仍受 4 MB 正文或 12 MB 图片上限约束。
- 代表图片和正文图片复用相同 SSRF 与跳转校验，单张限制为 12 MB、单篇本地化预算 48 MB，并同时核验 HTTP MIME 与 PNG/JPEG/WebP/GIF/AVIF/HEIC 文件签名。
- 正文图片本地化失败时转换为显式在线链接，不在阅读时静默加载第三方图片；文章会显示部分离线或仅正文离线。
- 微信公众号导入使用浏览器兼容请求头和专用静态解析器；环境验证页会被拒绝，不会作为文章写入。解析过程不执行页面脚本。

## 附件

- macOS 应用内文件入口使用 Chromium/Electron 的标准系统文件选择器。渲染器只接收用户明确选择的 `File` 对象，再经既有同源 HTTP 流式端点上传；该路径不向 preload 暴露真实路径、Node API 或任意文件读取能力。可见按钮与隐藏 input 位于同一受限组件，选择回调先建立请求体再清空 input。系统 Share Extension 的受限 token 桥另见下文。
- 单文件最大 100 MB，流式写入权限为 `0600` 的随机暂存文件。
- 文件名只作为显示信息；磁盘存储名由 SHA-256 和受限扩展名组成。
- 仅接受 PDF、常见图片/视频、Markdown 和纯文本；可执行格式被拒绝。
- 真实磁盘路径永不返回给前端。媒体端点强制 `nosniff` 并支持受控 Range。
- PDF.js 文本抽取与 PDF/图片缩略图解码在一次性权限和资源受限子进程中运行；长期服务进程只持有数据库事务、队列状态与最终文件落盘职责。
- 编辑器文章图片另设 20 MB 上限，只接受 PNG、JPEG、WebP、GIF、AVIF 和 HEIC，并同时校验文件签名；声明为图片的伪造内容会在挂载前删除暂存文件。
- 编辑器不提供附件物理删除，避免破坏文章历史版本中的资源引用。相同字节通过 SHA-256 复用本地文件。

## 自动订阅

- RSS、Atom 和 YouTube Feed 复用网页导入的公开 URL、DNS、重定向、超时与 4 MB 响应体限制。
- ETag 与 Last-Modified 只作为下一次同源请求的缓存校验头，不执行或解析为代码。
- 后台调度只处理已启用且到期的来源；单个来源同步去重，失败状态落库并指数退避，最长 24 小时，不会阻塞其他来源或主服务。
- OPML 使用无实体展开的受限属性解析，最多 500 个来源；每个地址仍逐一通过公开 URL 校验。导入错误按来源隔离并返回摘要。
- YouTube 只接受官方频道页、`/channel/UC…` 或 `feeds/videos.xml`，视频与播放列表地址不会被误当作频道订阅。
- X 只接受 1–15 位用户名或 `x.com`/`twitter.com` 用户主页；API 主机固定为 `api.x.com`，不接受用户提供的端点。Bearer Token 通过标准输入写入独立 macOS Keychain 项，不进入进程参数、SQLite、OPML、备份、导出或 API 响应。
- 微博只接受数字 UID 或对应个人主页。Reader 查找并直接执行开放平台官方 `@weibo-ai/weibo-cli`，关闭 shell，限制执行时间与 JSON 输出大小；OAuth Token 由 CLI 自己管理，Reader 不读取它。
- X 与微博图片在入库时复用现有公开 URL、重定向、MIME、签名、大小和 SHA-256 去重边界；下载失败会显式降级，不在阅读时静默加载。
- 社交游标、平台用户 ID、配额剩余和重置时间属于非敏感同步状态，可进入 SQLite 与 OPML 以外的本地运行记录；OPML 只导出账号主页和同步设置，不导出任何凭据。

## Markdown 与 AI

- Markdown 预览不启用原始 HTML，因此文章无法注入脚本或事件处理器。
- 高亮只保存用户主动选择的纯文本、有限偏移、允许的颜色和本地批注；不保存 DOM、HTML 或可执行内容。原文最长 5,000 字符，批注最长 20,000 字符，偏移必须是有界递增整数。
- 正文着色使用浏览器 CSS Highlight API，不向 Markdown 注入标签；正文变化导致锚点失配时只在本机按精确原文和最近旧位置重定位。
- 默认摘要和结构化整理完全本地。翻译只在用户启用有效的远程服务后可用，Reader 不提供会被误认为真实翻译的本地替代品。
- 界面会在发送前说明处理边界；远程请求只在用户点击生成、翻译或提问后发生。AI 状态 API 不返回端点和密钥。
- 单次跨文章创作最多 20 篇来源、约 24 万字符；请求 60 秒超时，响应最大 2 MB，网关结果必须是符合契约的 JSON。
- 派生文章保存在本地，并记录来源文章 ID/标题、任务、语言、提供方、模型、提示词版本和生成时间。远程服务自身的数据保留策略仍由服务提供者决定。
- macOS 上由 Reader 保存的 API 密钥进入独立的系统 Keychain 通用密码项；密钥不会写入 `settings.json`、SQLite、备份、导出或设置 API 响应。环境变量仍可作为未保存设置时的默认值。
- 非敏感的 AI 启用状态、提供商、端点、模型、本地语义检索 opt-in/模型和用户导入队列暂停偏好保存在权限为 `0600` 的 `data/settings.json`。远程端点强制 HTTPS，本机模型只允许回环 HTTP；URL 中的用户信息、片段和疑似密钥查询参数会被拒绝，OpenAI-compatible 基础地址还拒绝任何查询字符串。
- OpenAI 与 Ollama 预设分别锁定到 `https://api.openai.com/v1/` 和 `http://127.0.0.1:11434/v1/`，不能借预设名称改写目标主机。自定义 OpenAI-compatible 服务只接受用户明确提供的合规基础地址；模型 ID 最长 200 个字符且只允许受控 ASCII 字符。
- 模型目录只在用户点击后从同一基础地址的 `/models` 读取，不携带标题、正文、检索片段或资料库标识；响应沿用 60 秒、2 MB 边界，只返回最多 500 个合法且去重的模型 ID 与有限 owner 文本。Reader 不声称模型目录中的每一项都支持文本对话，最终仍以隐私连接测试为准。
- Keychain 密钥绑定到“提供商 + 规范化端点”作用域。候选测试和模型目录只有作用域未改变时才复用已存密钥；切换提供商或地址不会把旧密钥发送给新服务，保存新作用域且未输入新密钥时会删除旧 Keychain 项。设置写入失败则回滚本次凭据变更。
- 所有 AI 请求使用 `redirect: error` 拒绝 HTTP 跳转；用户必须保存最终基础地址，Reader 不依赖 Fetch 是否会在跨域重定向时剥离认证头来保护密钥。
- OpenAI-compatible 请求使用 `/chat/completions` JSON 模式；system 消息固定输出契约，并明确把文章、问题和提示词视为不可信来源数据。模型输出仍按现有字段、长度、引用 ID 白名单和 2 MB 总响应边界重新校验，不能直接写入任意引用或执行内容。
- 连接测试只发送 Reader 内置文本，不读取资料库正文；更新设置失败时会回滚本次 Keychain 变更。
- 本地语义检索默认关闭，且与远程 AI 提供商和 Keychain 凭据完全分离。嵌入只允许固定 `http://127.0.0.1:11434/api/embed`，不接受设置、环境变量或请求参数改写，不发送认证头并拒绝重定向；模型测试只发送 9 句固定的中文、英文和跨语言短句，不读取标题、正文、摘要、来源、标签或附件。响应只向界面返回模型、维度和三组聚合分离结果；点击启用后才把有限片段交给同机 Ollama。
- Ollama 嵌入批次最多 16 段、每段最多 2,000 字符，120 秒超时、8 MB 响应上限、8–4,096 维；所有分量必须为有限数并在落库前单位化。响应数量、维度和批内一致性必须精确匹配，不允许静默缺项或混合维度。
- `chunk_embeddings` 与 16 组 LSH 桶是可重建派生数据，不是正文事实来源。BLOB 长度、桶范围、模型一致性和外键由 schema v12 约束；正文变化会级联删除旧向量，模型维度变化会清空重建。关闭功能先确认当前批次结束，再删除全部向量和桶，文章、全文索引和远程 AI 设置不受影响。
- 向量查询只读取同一模型、活动文章和 LSH 命中的有限候选。每个 band 使用精确桶和两个最低置信位相邻桶，SQL 候选仍硬限制为 1,500，再在本机用完整向量计算精确余弦与词法混排；相邻桶不会直接成为相关性分数。Ollama 不可用、维度变化或索引未完成不会伪造语义结果，而是显式退回现有全文检索。后台建索引服从睡眠、低电量、严重热/降频和资料恢复锁。
- RAG 问答先在本机检索。远程网关只收到最多 8 个命中片段，每片最多 2,000 字符，不收到整篇文章或整个资料库；零命中时不发起远程请求。
- 引用 ID、标题、原文片段和偏移来自本地索引，不接受远程服务构造任意引用。远程返回的 `citationIds` 只允许引用本次已发送的候选集合。
- 弱相关候选必须通过词组覆盖与相对分数阈值；证据不足会显式返回空引用，避免把无关内容包装成依据。

## 备份与恢复

- 备份使用 SQLite 一致快照，不直接复制运行中的 WAL 数据库。
- 0.52 起，创建成功必须同时证明输出可读：Reader 先对 `VACUUM INTO` 快照执行 SQLite 完整性检查，再从生成的 ZIP 流式重读数据库、manifest 和全部附件，逐项核对真实字节数与 SHA-256。验证过程不把整套附件再解压到磁盘；任何缺失、重复、未知、越界或哈希不一致都会删除本次输出并返回失败。
- 加密备份先验证尚在权限受限暂存区的完整 ZIP，再执行 AES-256-GCM 加密；最终密文会立即通过同一口令认证解密到内存哈希 sink，并要求得到与已验证 ZIP 相同的 SHA-256。只有两层都通过后才创建验证凭据和返回成功。
- 创建时验证凭据以独立 `0600` JSON 文件保存在 `data/backups/`，只记录备份 ID、严格文件名、字节数、归档 SHA-256 和验证时间。列表只在凭据格式、ID、文件名和当前字节数全部匹配时显示“创建时已校验”；旧备份或损坏/缺失凭据仍可列出并在恢复时执行完整验证，不会被伪装成新验证结果。
- 每日自动恢复点默认关闭，只有本机用户在数据安全中心明确开启后才写入 `settings.json`；缺失字段、非布尔值或设置读取失败均保持关闭。自动任务不保存或复用口令，只创建包含 SQLite、附件和 SHA-256 manifest 的本机明文完整备份。
- 自动恢复点使用独立且严格的 `reader-auto-backup-…readerbackup.zip` 文件名；轮转只枚举这个受限命名空间并保留最新 3 份，不删除普通、加密、`pre-repair`、`pre-restore` 或 `pre-migration-restore` 备份。关闭功能不会删除已经创建的恢复点。
- 自动任务每 24 小时最多创建一次；导入正在运行时延后，在睡眠、低电量、严重热/降频或资料恢复锁下暂停。暂停会等待已经开始的一致性快照和附件归档完成，恢复流程不会与它并发跨越备份边界。
- schema 升级同样在任何结构变更前使用 `VACUUM INTO` 创建一致快照，校验 `integrity_check` 后以 `0600` 权限保存在 `data/migration-backups/`；快照列表只接受 Reader 生成的严格文件名，下载以不缓存、`nosniff` 的私有端点提供且不暴露磁盘路径。检测到高于当前支持版本的 schema 时拒绝降级打开，不执行写入或迁移。
- 升级快照恢复只接受本机列表中的快照 ID，不接受任意 SQLite 上传。安排和实际启动替换前均验证文件哈希、实际来源 schema、SQLite 完整性与外键；未来 schema 快照会被拒绝。Reader 先暂停导入与订阅并创建包含当前数据库和附件的完整安全备份；待恢复期间写 API 失败闭锁，只读浏览和资料库检查可继续，取消后恢复后台任务与写入。下次启动仅替换数据库、保留附件并重新执行受审计迁移。升级后新增或修改的数据库记录不会留在活动资料库，但仍可从安全备份恢复。
- schema v8 作为不可变 bootstrap；后续迁移按连续版本注册，每个版本在单独事务内同时提交结构、版本号与审计记录。启动时核对迁移的固定名称和 SHA-256，已发布历史缺失、未知或被改写时停止打开。
- 资料库体检必须由本机用户打开数据安全中心或调用 POST API 明确触发；检查过程不写 SQLite，响应只含状态、数量、耗时和数据库大小。正文、标题、附件名、存储名、记录 ID、错误原文与磁盘路径均不返回；内部文件错误统一映射为通用响应。
- 受控修复必须由用户在数据安全中心确认或显式调用 POST API；同一时间只运行一项修复，导入任务或待重启恢复存在时拒绝开始。
- 自动修复只允许收紧数据目录、数据库和 SQLite sidecar 权限，或从权威文章表重建词法全文、trigram 子串和 RAG 派生索引。索引写入前必须创建完整 `pre-repair` 备份，写入后重新执行全套健康检查；失败时备份保留。
- SQLite 页损坏、外键失效、迁移历史异常、附件缺失或大小不符会关闭自动修复。Reader 不自动伪造附件、删除未引用文件、修改正文或猜测关系；修复 API 不返回正文、附件名、存储名、记录 ID、manifest 或磁盘路径。
- 归档只允许 `reader.sqlite3`、`manifest.json` 和 `files/`；拒绝绝对路径、`..`、反斜杠、符号链接和未知路径。
- 解压限制条目数、单条目声明大小和总展开大小，防止路径穿越与压缩炸弹。
- 恢复前验证 manifest 版本、数据库哈希、每个附件哈希和 SQLite `integrity_check`。
- 恢复只安排在下次启动执行；Reader 会先创建一份恢复前安全备份，再原子替换数据库和文件目录。
- 加密备份使用随机 salt、scrypt（N=65536、r=8、p=1）和 AES-256-GCM；格式头作为附加认证数据，密文任何位置被修改都会导致恢复失败。
- 备份口令至少 12 个字符，只在当前创建或恢复请求的内存中使用，不写入数据库、manifest、日志或待恢复标记。遗忘口令后无法恢复。
- 解密结果仅写入权限为 `0600` 的随机恢复暂存目录；认证或后续完整性校验失败时整个目录被清理。

## 外部添加入口

- `reader-local` 是传递意图的自定义 scheme，不是可信来源或网络协议。任何本机应用和网页都可能尝试唤起它，因此 Reader 只接受固定 `add` 动作，以及互斥且唯一的 `url`、`text` 或 `file` 参数；混合、重复、额外参数和其他输入不会传给渲染器。
- URL 最长 2,048 字符，必须是无凭据的 HTTP(S) 目标。文本使用无 padding 的规范 Base64URL，解码后必须是非空、最多 4,096 UTF-8 bytes 且不含禁止控制字符的有效 UTF-8；换行、回车和 Tab 保留。文件参数只能是小写规范 UUID v4，不携带路径或元数据。外层深链最长 8,192 字符。
- 主进程与 preload 分别重新校验并把待处理数量限制为 20。内容不会写入诊断日志，preload 只公开冻结请求对象的单向订阅回调；文件另有 inspect/import/discard 三个只接受 token 的受限调用，不公开通用 IPC。
- 合格深链只聚焦 Reader 并预填“添加内容”窗口。用户取消时不创建任务或文章、不发起 DNS 或 HTTP 请求、不写入 SQLite；只有点击 URL/附件页的“加入导入队列”或 Markdown 页的保存按钮后才进入既有本地 API。文件扩展为跨越 `NSItemProvider` 回调生命周期而创建的临时副本不属于资料库写入，受下述权限、完整性和清理规则约束。
- 服务端仍重新执行 URL 语法、用户名/密码、DNS 全量解析、私网/元数据地址、重定向和响应体限制。深链预检不代替、缓存或削弱该权威校验。

## 本地诊断日志

- Reader 不启用遥测，也不自动上传诊断数据。本地日志只在本机回环 API 和数据安全中心中可见，用户可以导出或清除。
- 日志事件与字段均为代码内固定白名单。禁止记录标题、正文、摘要、URL、来源名、附件名、存储名、记录 ID、磁盘路径、错误原文、堆栈、API Key、社交令牌或备份口令；未知事件和未知字段直接丢弃。
- 意外服务错误只记录请求方法、无 ID 的功能分组、HTTP 状态与有限错误类别；渲染器只收到“无法完成请求”，不收到内部异常文本。JSONL 读取与导出再次清洗，不能借由篡改本地日志让任意内容进入响应。
- 渲染进程异常退出只记录 Electron 固定枚举中的原因；exit code、进程 ID、页面 URL、路径、堆栈和未保存输入都不会写入日志。未知原因统一收敛为 `unknown`。
- `data/logs/` 为 `0700`，日志文件为 `0600`；每个文件最多 512 KB，最多三份，超出自动轮转。日志不进入完整备份、Markdown 导出或设置文件，日志写入失败也不会阻断资料库。

## 本机系统通知

- 后台导入与后台订阅通知使用两个独立开关，均默认关闭；只有用户在 Mac App 设置中明确开启后才写入 `settings.json`。旧设置缺失字段、非布尔值或读取失败都保持关闭，更新一项不会隐式开启或关闭另一项。通知开关不进入备份或导出。
- 导入 worker 不把任务、文章或异常对象传给主进程，只按一轮最多 20 项汇总成功/失败数量。订阅调度器同样只汇总自动批次的新增内容数与失败来源数；手动同步不进入通知回调，全零批次不显示。两类通知均使用固定模板，禁止包含标题、正文、摘要、URL、来源、附件名、磁盘路径、任务/文章/来源 ID、资料夹、错误原文、堆栈或凭据。
- Reader 任一窗口位于前台、应用正在退出、系统不支持通知或 macOS 拒绝显示时不降级为网页通知、不扩大权限、不记录系统错误原文，也不影响导入或同步结果。点击导入通知只打开既有导入队列；点击订阅通知只打开既有内容来源。
- macOS 通知依赖操作系统 UNNotification 与代码签名。正式发行必须在 Developer ID 签名/公证包上验证授权、显示、点击和关闭；ad-hoc 包不能作为正式可用性证据。

## 专注阅读窗口

- 渲染器不获得任意窗口创建或导航能力。preload 只接受最长 200 字符且不含控制字符的文章 ID，并通过固定 `reader:open-article-window` 通道请求；主进程再次验证发送 frame 的精确随机回环 origin，并向 SQLite 确认 ID 存在。
- 每个文章 ID 最多保留一个窗口。窗口与主界面使用相同的 sandbox、context isolation、CSP、网页权限拒绝、外部链接转交和跨 origin 导航拒绝设置，不允许页面覆盖 `BrowserWindow` 选项。
- 专注窗口的正文、附件与既有高亮从同源本地 API 读取。界面明确进入只读模式，不调用收藏、移动、归档、标签、阅读进度、高亮或批注写 API；返回资料库 IPC 只恢复和聚焦主窗口，主窗口已关闭时使用原有窗口配置重建。
- 任一主窗口或专注窗口处于前台时均抑制后台导入和订阅通知，避免用户正在 Reader 中阅读时出现自有通知。

## macOS Spotlight

- Spotlight 索引是独立、默认关闭的 opt-in。旧设置缺失、类型错误或文件读取失败都保持关闭；源码模式、非 macOS 或缺少签名 helper 时不能启用。
- 开启后写入标题、最多 2,000 字摘要、最多 20,000 字正文、作者、来源、类型、语言、标签及时间。索引使用首次解锁后可用的数据保护级别和 Reader 专属 domain，只存在当前 Mac，不进入 Reader 备份、Markdown 导出或其他设备同步。
- SQLite outbox 先记录文章/标签变化，Core Spotlight 确认后才按 revision 删除。失败只保留待重试状态，UI 与日志不接收 helper 原始错误或被索引内容；正文通过 stdin 发送给嵌套 helper，不进入 argv 或继承环境。
- helper 每批最多 100 条、输入最多 3 MiB，并对 ID、字段长度、命令和输出设硬限制。Node 侧限制运行时间与输出，使用最小环境；helper 不联网、不读 Reader 数据库，也不接受任意文件路径。
- 系统结果只生成 `reader-local://open?article=<id>`。Swift helper 与 Electron 主进程分别校验固定前缀、长度、控制字符和唯一参数，主进程还确认文章真实存在；无效结果不会打开窗口、网络或文件。
- 关闭时 Reader 必须先确认专属 Spotlight domain 已删除，之后才保存关闭并清空 outbox。删除失败时设置保持开启并返回通用错误，避免把“已关闭”误报成“系统仍留有索引”。

## macOS Share Extension

- `.appex` 只声明严格匹配的单个网页 URL、单段文本或单个文件。URL 与文本继续受 2,048 字符/4,096 UTF-8 bytes、协议、凭据、控制字符和规范编码限制；文件只接受 PDF、PNG/JPEG/GIF/WebP/HEIC、MP4/MOV/M4V/WebM、Markdown 或纯文本的受控 UTI 映射，必须是非空普通文件且最多 100 MB。文件夹、符号链接、可执行格式和其他类型被拒绝。
- Apple 会在 `loadFileRepresentation` 回调返回时删除其临时副本。扩展因此在回调内复制到自身 `Caches/ReaderShareStaging`：目录 `0700`、载荷和描述 `0600`，随机 UUID v4 为文件名，描述文件固定记录版本、token、安全显示名、受控 MIME、字节数、SHA-256 和 ISO 创建时间并最后原子写入。扩展启动时清理超过 24 小时的成对暂存，打开 Reader 失败时删除本次副本。
- 扩展签名仍只包含 App Sandbox entitlement，不申请网络、用户文件、App Group、Keychain、书签或硬件能力，也不读取 Reader 数据目录。URL 使用 `URLComponents`，文本使用无 padding 规范 Base64URL；文件深链只含随机 token，不含路径、名称、MIME、大小、摘要或内容。
- Electron 主进程只从当前用户固定的扩展缓存目录解析 token。目录不能是符号链接；描述与载荷均以 `O_NOFOLLOW` 打开并要求普通私有文件，随后核对精确 schema、时间窗口、大小、SHA-256、文件名和类型。preload 再次校验 token 与返回元数据，只向受信任回环页面公开 inspect/import/discard，不公开路径或任意文件读取。
- 用户先在系统分享菜单明确选择“存入 Reader”，随后还必须在 Reader 内核对名称和大小、选择资料夹并确认。确认前不创建 SQLite 记录或导入任务；确认时主进程从已验证文件描述符流式写入既有随机回环上传端点，服务端再次执行文件名、MIME、大小、图片签名和持久化队列校验。成功、取消或切换入口会删除暂存，传输失败可重试并最迟在 24 小时后清理。
- Share Extension 不写诊断日志或共享历史，暂存不进入 Reader 备份、导出、设置或 SQLite。SHA-256、权限和 token 防止意外混淆、路径注入及低权限跨用户读取；它们不声称防御已经取得当前用户权限并可直接读取或修改 Reader 数据的进程。系统若没有启用扩展，用户需从分享菜单的“编辑扩展”手动启用；Reader 不调用 `pluginkit` 修改用户偏好。
- 正式签名流水线关闭 entitlement 自动补全，为主程序使用仅含 V8 JIT 的显式权限；产物回读要求主程序、Share Extension 与 Spotlight helper 分别精确等于 `allow-jit`、App Sandbox 和空集合，拒绝额外 App Group 或硬件能力。扩展在父 App 重签后再次验证，避免深度签名静默剥离。

## 应用更新

- 只有打包后的 macOS App 且 `/usr/bin/codesign` 同时报告 `Developer ID Application` authority 与有效 Team Identifier 时，Reader 才设置更新 feed。开发模式、ad-hoc、Apple Development 或异常签名包不连接更新服务；这也保证当前本地交付不会静默获得未验证代码。
- 更新地址固定为公开 `Leo-Cjw/Leo-Reader-App` 仓库的 `update.electronjs.org` universal macOS 路由，不接受用户输入、自定义查询参数、凭据或私有令牌。更新检查不读取或上传资料库、设置、诊断日志和本机路径。
- 正式更新 ZIP 只在 Developer ID 签名与 App 公证均成功后生成。脚本要求公证票据可验证，压缩后再解压，并对解压 App 重做深度严格签名和票据验证；ad-hoc 流水线主动删除同版本残留 ZIP。
- Electron 下载更新后不会直接中断用户工作。只有用户确认“重启并安装”，Reader 才先停止后台任务、刷新诊断缓冲并关闭本地服务，再调用系统更新器。更新包不包含独立存放在 Application Support 下的资料库。

## 依赖审计

- 发行门禁分别审计生产依赖和完整构建依赖。生产依赖必须在 `low` 阈值下保持 0 个已知漏洞；任何新增或未评估的构建公告同样使门禁失败。
- 0.34 把运行时 ZIP 库升级到 Archiver 8，使生产树使用修复了 CVE-2026-14257 的 `brace-expansion` 5.0.8。文章、附件或备份文件名不会进入 glob brace pattern。
- Electron Builder 26.15.3 与 `@electron/universal` 2.0.3 仍固定依赖旧版 minimatch/brace API；上游尚无兼容 Node 20 的修复版本。该公告只允许存在于 devDependency 构建树，输入是仓库内固定 `files` globs 和受控源码文件名，不进入 Reader App、用户导入或本机服务运行时。审计脚本只放行这一条精确 GitHub Advisory；上游发布兼容修复后应立即移除例外。

## 只读正文键盘选区

- 屏幕阅读器文章描述只重用当前列表响应已经加载的摘要字段，不读取完整正文、不触发额外 API，也不写入日志或网络请求；标签最多三个，摘要最多 180 字。描述内容仍只存在于本机渲染器与操作系统可访问树中。
- 键盘选取模式不设置 `contenteditable`，不向静态正文开放输入、删除、粘贴、拖放或输入法编辑面。方向键只通过浏览器原生 Selection/Range 改变临时选区；正文和文章版本均不写入。
- 只有用户在保存浮层确认后，受限的 quote、起止偏移、颜色与可选批注才通过既有高亮 API 写入 SQLite。Escape 或取消会清除 Range 且不创建记录。
- Control+Option 方向键不被 Reader 拦截，避免覆盖 VoiceOver 导航组合键。选区状态只播报当前本机正文的有限可见片段，不进入诊断日志、设置或网络请求。

## 辅助技术状态

- 产品导航、内容区、阅读器和文章助手的 landmark 名称只来自固定界面文案或当前已经载入的本地文章标题，不触发额外数据库、文件或网络读取。
- 文章切换的 polite live status 只播报“正在载入/已载入”和当前标题；详情尚未匹配当前文章 ID 时不向阅读器或文章助手暴露上一文章正文。
- 顶层模态框打开时，主窗口及较低层模态框使用浏览器原生 `inert`，避免被鼠标、键盘、程序化焦点或辅助技术继续操作。inert 只改变当前渲染器交互树，不读取正文、不写入资料库，也不扩大 preload 或 IPC 权限；全部窗口关闭后立即清除。
- macOS 发行前可访问性门禁只以 `127.0.0.1` 随机调试端口连接本轮自己启动的候选 App，并把 Chromium profile 与 Reader 资料根目录放进权限受限的临时目录。QA 环境仅跳过默认 URL scheme 注册；退出会终止自己的进程并删除临时资料，不读取或改变用户现有 Reader 数据、系统分享偏好、Spotlight 设置或协议处理器。调试端口不会进入正常产品启动参数。
- macOS“减少动态效果”只改变 CSS 动画、过渡和本机滚动方式，不写入设置、诊断日志或资料库，也不改变任务状态。

## 可迁移导入导出与重复治理

- 导出仅接受本地文章 ID，单次最多 500 条；附件路径必须解析在 `data/files/` 内，缺失或越界会拒绝整次导出。
- ZIP 中的 Markdown 使用安全文件名和相对附件路径；manifest 和 v3 sidecar 不写入数据库路径、附件存储名、AI 密钥、社交令牌或备份口令。
- 导出响应禁止缓存并强制 `nosniff`。导出属于用户主动下载，不改变本地文章状态。
- Markdown ZIP 导入只接受 `reader-markdown-export` v2/v3；其他 ZIP、完整备份和任意 Markdown 压缩包不会走这条写入路径。
- 预检拒绝绝对路径、`..`、反斜杠、符号链接、加密条目、重复路径和清单以外文件；压缩包上限 2 GB、展开总量上限 5 GB、单附件上限 100 MB、文章上限 500 篇，并限制条目数量和单个 manifest/Markdown/sidecar 大小。
- 每个清单附件在预览阶段重新核对实际字节数与 SHA-256；清单统计、文章/附件 ID、记录路径、URL 协议、高亮范围和阅读进度也必须通过受限校验。
- 暂存根目录与导入目录权限为 `0700`，文件为 `0600`；预览 token 为不可推导 UUID，API 不返回磁盘路径。取消、提交或 24 小时过期都会递归清理暂存包。
- 用户必须逐篇选择并指定资料夹；相同 Reader ID 或 HTTP(S) 原链接默认跳过，导入不会隐式合并或覆盖现有文章。
- 重复检测只使用本地精确规范化哈希，不会联网。整理操作不删除文章或附件，副本移入归档并记录保留版本 ID，可人工恢复。

## 智能资料夹与拖放

- 智能资料夹规则只接受已知字段、受限内容类型、最多 10 个标签、最长 200 字符关键词、最长 120 字符来源，以及 1–3,650 天的时间窗口；空规则被拒绝。
- 规则值全部经过 SQL 字面量转义，不接受客户端 SQL、列名、排序表达式或可执行代码。“任一满足”仍始终附加未归档基础条件。
- 智能资料夹只保存规则和顺序，不复制、移动或删除文章；删除智能资料夹不会改变任何内容。
- 拖放文章复用现有原子批量移动接口，一次最多 500 条。资料夹排序要求完整同级 ID 集合，缺失、重复或跨层列表会被拒绝。

## 缩略图

- 网页 DOM、PDF 文本和图片/PDF 缩略图不在长期运行的本地服务进程解析。一次性解析进程使用 256 MB V8 heap、15/30 秒超时、12 MB IPC 上限、最多 2 个并发和 32 个排队任务；异常退出只影响当前可重试任务。
- 解析器只继承最小环境，并在目标 Node/Electron 中启用 permission model：只读应用代码和当前源文件，拒绝文件写入、任意系统文件读取与嵌套子进程。每次响应以随机 nonce 定界，父进程重新验证结构和大小。
- 图片和 PDF 缩略图只在本机生成，源文件上限 100 MB，图片解码后拒绝超过 1.6 亿像素的内容。图片解码依赖项目自带原生 Canvas addon，因此缩略图任务允许该受信任 addon；子进程隔离不等同于完整 OS 沙箱。
- PDF.js 禁止动态求值且只渲染第一页；输出为固定尺寸 WebP，不携带原始文档脚本或链接。
- 缩略图缓存不进入备份，资料库恢复后自动清空。

## 导入队列控制

- 用户暂停偏好只接受布尔值并原子写入本机设置；不包含任务载荷、URL、文件名或磁盘路径，也不进入备份和 Markdown 导出。
- 暂停先阻止 worker 领取下一项，已经运行的单项任务完成后进入稳定暂停。应用重启会在本地服务开放前恢复暂停状态，pending/running 恢复规则仍由持久化队列负责。
- 用户继续只清除 `user` 原因。资料恢复锁、Mac 睡眠或系统严重受限仍会保持队列暂停，不能通过控制端点绕过。
