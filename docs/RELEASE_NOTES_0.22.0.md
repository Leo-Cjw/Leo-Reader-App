# Reader 0.22.0

本版本让 Reader 的资料列表在大规模本地库中保持完整、可解释和可感知流畅。此前数据库只返回前 100 条，界面却把已返回数量当作全部结果；超过 100 条的资料会被静默隐藏。0.22.0 增加稳定游标分页、准确命中总数、复合排序索引和中文子串全文索引，并把 10 万条规模写入独立性能门禁。schema 从 v9 升级到 v10，结构变更前仍会自动创建一致性快照。

## 完整分页

- `GET /api/articles` 现在返回 `articles`、`total`、`hasMore` 和不透明的 `nextCursor`；后续页只需把游标原样传回 `cursor`。
- 页面按 `(created_at, id)` 倒序读取，创建时间相同仍保持确定顺序；格式无效的游标返回 400，不进入 SQL。
- 数据库既有 `listArticles()` 数组契约保持兼容，分页元数据由新增的 `listArticlePage()` 提供。
- 界面明确显示“已加载 100 / 共 N 条”，在列表和画廊底部提供加载更多；追加结果按 ID 去重，加载完毕后显示准确总数。
- 快速搜索或筛选切换使用请求代次丢弃过期响应；30 秒后台状态刷新不再把用户已经加载的页面重置为首屏。
- “选择全部”明确限定为已加载内容，批量整理、导出和创作不会暗示选择了尚未加载的记录。

## 10 万条性能

- schema v10 为归档、未读、收藏、内容类型和资料夹视图增加与倒序分页匹配的复合索引。
- 三个及以上字符的中文查询使用 FTS5 trigram 子串索引，不再对标题、摘要、正文、作者和来源执行全表 `LIKE` 扫描；一至两个字符保留兼容路径。
- trigram 索引通过独立触发器随文章增删改更新；资料库体检会同时核对词法全文、trigram 和 RAG 分块索引行数。
- 受控修复会在完整安全备份后重建三套派生索引，正文、状态、版本、标签和附件保持不变。
- `npm run benchmark:library` 创建 100,000 条合成资料，重复测量统计、首屏、第二页、中段游标、未读筛选和中英文搜索；任一交互 p95 超过 250 ms、分页重复或计数不完整都会失败。

## 质量门禁

- 80 项自动测试覆盖稳定游标、同时间记录顺序、准确总数、分页无重复、游标拒绝、中文子串命中、索引损坏检测/安全修复和连续 v7→v10 / v8→v10 迁移。
- 真实浏览器使用 128 条临时资料完成首屏、加载更多、中文混合查询和视觉回归：100→128 条无重复，计数/按钮状态正确，控制台无警告或错误。
- 100,003 条最终基准中：统计 p95 131.71 ms，首屏（含准确总数）25.57 ms，第二页 11.15 ms，中段游标 10.45 ms，未读筛选 19.54 ms，英文搜索 22.60 ms，中文搜索 19.82 ms，全部低于 250 ms 门禁。建立测试库和双全文索引用时 40.8 秒。
- 10,003 个本地 RAG 片段、30 次查询的检索基准 p50 为 25.42 ms、p95 为 26.48 ms，低于 250 ms 门禁。
- TypeScript/Vite 生产构建通过，依赖审计为 0 个已知漏洞。
- Universal App 检出 `arm64` 与 `x86_64` 双架构，版本元数据为 0.22.0，ad-hoc 深度签名验证通过；DMG 通过 `hdiutil verify`。
- `Reader-0.22.0-universal.dmg` 大小为 254,440,695 字节，SHA-256 为 `868d4f3967e4ec51895da2f2c3757c418ca6cadfe28c934eec981391bb90e79d`。

## 已知边界

- 首次升级到 schema v10 会为现有正文建立 trigram 索引；这是一次性本地操作，大资料库所需时间和磁盘空间随正文总量增长。结构变更前会先创建升级快照。
- 一至两个字符的中文搜索仍使用兼容扫描；短词搜索在超大资料库中可能慢于三个及以上字符的查询。
- 列表 API 当前仍携带完整正文。游标避免了一次加载整个资料库，但长正文负载的进一步瘦身仍是后续性能工作。
- Developer ID 正式签名、Apple 公证、自动更新和 Apple Silicon 真机安装升级验收仍未完成。
