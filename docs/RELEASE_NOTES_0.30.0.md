# Reader 0.30.0

本版本把所有本地文件入口统一为明确、可聚焦的系统文件选择按钮，并修复最终打包 App 在页面已经加载时仍可能没有显示窗口的发行阻断问题。资料库 schema 仍为 v10，上传 API、备份格式和既有文件校验边界保持兼容。

## 系统文件选择器

- 附件、Markdown 编辑器图片、Reader ZIP、OPML 和备份恢复五条路径不再依赖透明覆盖或微小文件输入框，均以具名原生按钮呈现，并具有可见的 `:focus-visible` 状态。
- 按钮只触发同组件内的标准隐藏 `input[type=file]`；选择结果以浏览器 `File` 对象进入既有同源流式上传，不向渲染器暴露磁盘路径，也没有新增 Electron 文件读取 IPC 或 preload 桥。
- 选择回调在清空 input 之前建立请求体，避免立即上传因文件句柄提前释放而失败；随后清空值，允许用户重新选择同一个文件。
- 附件、Reader ZIP 和备份恢复在选中后会把当前文件名纳入按钮的可访问名称，备份入口继续按文件类型显示加密口令字段。

## 打包窗口可靠性

- 最终 Mac 包回归发现：本地服务、渲染器和首屏绘制均已完成，但只依赖 `ready-to-show` 的窗口可能没有显示。这一问题在发行前被视为阻断项并修复。
- 主进程现在等待本地页面 `loadURL` 成功，在窗口仍有效时显式调用 `show()`；既避免空白窗口，也不再依赖可能缺失的单一事件。
- 重新打包后的 App 由 CoreGraphics 确认 `Reader — 本地阅读工作台` 窗口在屏幕显示，最终渲染文档为 visible。最终包内附件按钮可见，真实坐标点击触发 `selectSingle` 文件选择器事件。

## 浏览器回归

- 隔离资料库真实浏览器回归确认五个入口都能发出文件选择器事件；附件、Reader ZIP 与备份恢复还验证了文件选择后的动态名称、附加状态和焦点返回，按钮保持 `:focus-visible`。
- 编辑器图片入口报告多选模式，其他入口为单选。该浏览器自动化环境没有把 OPML 和编辑器图片的自动 `setFiles` 转换为可观察上传请求，因此不把这两条前端上传声称为端到端浏览器成功；既有 API 自动测试继续覆盖 OPML 解析导入和编辑器图片上传、签名校验与去重。
- 回归没有读取、输出或记录任何真实文件路径；隔离标签页、服务和临时资料库均已关闭或移入废纸篓。

## 已知边界

- 当前本地包仍缺少真实 Apple Developer ID、公证凭据、正式 GitHub Release 与 Apple Silicon 真机 Gatekeeper/跨版本升级验收；ad-hoc 包不会连接自动更新服务。
- 文件入口已验证键盘焦点、可访问名称与选择器触发，但尚未在启用 macOS VoiceOver 的真机上逐项听读；完整 VoiceOver 审计仍是下一阶段工作。
