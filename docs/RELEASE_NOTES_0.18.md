# Reader 0.18.0

本版本优先加固资料库升级链路。Reader 现在会把每次已发布 schema 变更视为可验证、不可静默改写的产品接口；升级前恢复点也继续保留在数据安全中心。

## 顺序迁移与审计

- Schema v8 固定为不可变 bootstrap；v9 及后续变更只通过连续的迁移注册表追加。
- 每个版本使用独立 SQLite 事务，同时提交结构变更、schema 版本和审计记录；失败时三者一起回滚。
- Schema v9 新增迁移审计表，保存固定名称、SHA-256 校验值和应用时间。
- 每次启动会核对目标版本、连续迁移历史和审计校验值；未知、缺失或被改写的历史会停止打开，避免不兼容代码继续写入。

## 升级恢复点

- 检测到旧资料库后，Reader 在任何结构变更前使用 `VACUUM INTO` 创建一致快照并执行 `integrity_check`。
- 快照目录权限为 `0700`，文件权限为 `0600`；文件名记录原 schema 与目标 schema。
- 数据安全中心可以列出并导出恢复点，API 不暴露真实磁盘路径。
- 来自未来 schema 的资料库仍会原样拒绝，不创建快照或执行写入。

## 版本一致性

- 应用、健康检查、完整备份和 Markdown 导出统一使用 0.18.0。
- 服务端版本由单一常量提供，并由自动测试核对 `package.json`，减少发行元数据漂移。

## 质量门禁

- 60 项自动测试全部通过，包括 v7→v9、v8→v9、迁移幂等、用户数据保留、审计防篡改、未来版本拒绝和故障事务回滚。
- TypeScript/Vite 生产构建通过，依赖审计为 0 个已知漏洞。
- 10,003 个本地片段、30 次查询的检索基准 p95 为 39.13 ms，低于 250 ms 门禁。
- 0.18.0 Universal App 检出 x86_64 与 arm64 双架构，ad-hoc 深度签名验证通过；DMG 通过 `hdiutil verify`，SHA-256 为 `1871cfc4c80e358b7b67faa07b0f46897cc9fb6c99d530163a9d26128c1b74c4`。

## 已知边界

- Developer ID 正式签名、Apple 公证和自动更新仍未完成。
- 最近一次 x64 真机升级与完整交互验收针对 0.17；0.18 Universal 包已经完成结构、签名和镜像验证，仍需在 Intel 与 Apple Silicon 真机完成安装、升级、重启和 Gatekeeper 验收。
- 数据安全中心目前支持导出迁移快照，尚未提供面向用户的一键回滚；需要恢复时应保留当前库并由受控流程操作。
