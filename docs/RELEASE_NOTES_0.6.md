# Reader 0.6.0

本版本把“手动刷新 RSS”升级为可长期运行、可迁移、可观察的本地订阅系统。

## 自动订阅

- RSS、Atom 与 YouTube 频道共用统一同步服务；YouTube 支持频道主页、`/channel/UC…` 和官方 Feed 地址。
- 后台调度每 30 秒领取到期来源，支持 15 分钟、30 分钟、每小时、每 6 小时、每天和每周频率。
- 保存 ETag 与 Last-Modified，HTTP 304 不重新解析或制造重复内容。
- 同一来源的手动与后台同步合并为一个进行中任务；成功、无更新、失败、HTTP 状态、连续失败、最近新增数和下次运行时间全部写入 SQLite。
- 失败采用指数退避，最长 24 小时；来源之间故障隔离，不阻塞应用和其他订阅。

## OPML 与来源管理

- 支持 OPML 2.0 导入导出，保留 Reader 的来源类型、启用状态与同步频率；重复来源安全跳过。
- 导入最多 500 个来源，每个 URL 单独经过公开网络校验；单项失败不会让其他有效来源回滚。
- 新增来源更新、暂停/开启、频率修改与删除 API。删除来源不会删除已经保存的文章。

## 订阅中心

- 新的订阅中心延续 Reader 的低噪声桌面设计，集中显示全部来源、自动同步数和需处理数。
- 每行展示来源类型、健康状态、URL、上次/下次同步、最近新增与错误，并提供开关、频率、立即同步和删除。
- “添加”窗口统一支持 RSS/Atom 与 YouTube，创建后立即完成首轮同步。
- 应用在后台刷新来源、文章和计数，不需要用户重新载入页面才能看到自动同步结果。

## 数据迁移与质量

- Schema v4 对 0.5 及更早的 `sources` 表执行幂等列迁移；旧来源默认 60 分钟并安排安全首轮同步，启动时清理残留 `syncing` 状态。
- 29 项自动测试覆盖旧库升级、成功同步、HTTP 304、失败退避、到期调度、OPML 往返、来源 HTTP API及既有产品链路。
- 发布门禁保持为 `npm audit --audit-level=moderate`、`npm test` 和 `npm run build`。

## 尚未包含

- X 与微博需要可持续的官方连接方式和安全令牌生命周期，本版本没有模拟或抓取式假连接器。
- 原生 macOS 壳、Keychain、Share Extension、签名与公证需要完整 Xcode/Swift 工具链，进入 M3。
