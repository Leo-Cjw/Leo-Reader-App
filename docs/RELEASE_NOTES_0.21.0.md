# Reader 0.21.0

本版本补齐 schema 升级快照的受控恢复闭环。用户可以在数据安全中心把资料库安排回升级前状态；Reader 会先保存当前数据库和全部附件的完整安全备份，再于下次启动原子替换 SQLite 并重新执行现有受审计迁移。schema 仍为 v9，0.20.1 用户升级不需要数据库迁移。

## 受控升级快照恢复

- 只接受当前 Reader 数据目录中按严格文件名枚举得到的快照 ID，不接受上传任意 SQLite 文件。
- 安排恢复前核对目标版本不高于当前应用、实际来源 schema 与快照记录一致，并验证 SQLite 完整性、外键和 SHA-256。
- 快照会复制到权限为 `0700/0600` 的独立待恢复目录；下次启动替换前再次执行同一组校验，发生篡改或损坏时保持当前资料库不变。
- 替换只作用于 SQLite；升级前已经存在的附件继续留在原位置，可再生缩略图会清空。替换后统一经过连续迁移注册表和固定校验值审计。
- 安排前自动创建 `pre-migration-restore` 完整备份，保存当前数据库与全部附件。快照以后新增或编辑的记录不会出现在恢复后的活动资料库，但可从这份安全备份恢复。
- 待恢复期间服务端冻结资料库写请求，并暂停导入队列与订阅调度，避免安全备份完成后又产生会在替换时丢失的新变化；只读浏览和资料库检查仍可使用。
- 待恢复状态会显示来源 schema、重新迁移语义、安全备份承诺和写入暂停；任务可在重启前取消，取消后写入与后台任务恢复，原快照和已创建的安全备份不会删除。

## API 与本地诊断

- 新增 `POST /api/migration-snapshots/:id/restore`；导入任务或受控修复运行时拒绝安排，未知或未来版本快照失败闭锁。
- API 只返回快照 ID、schema 范围、时间与安全备份 ID，不返回待恢复目录或数据库哈希。
- 本地诊断日志只记录恢复来源为完整备份或升级快照，不记录快照 ID、文件名、路径或哈希。

## 已知边界

- 快照恢复是针对已修正迁移代码的补救路径；若当前版本仍包含同一迁移缺陷，重新迁移可能再次失败，此时应使用自动创建的完整安全备份恢复。
- 升级快照只包含 SQLite，不是长期完整备份；正式备份仍应包含附件，并优先使用口令加密。
- HTML、PDF 与媒体元数据解析仍在主本地服务进程内；后续仍需迁移到资源受限的隔离进程。
- Developer ID 正式签名、Apple 公证、自动更新和双架构真机安装升级验收仍未完成。
